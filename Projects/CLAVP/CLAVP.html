Welcome to my A-level Computer Science project! I worked on this project for the bettermost of the 2nd year of my A-levels (2019). The project allows users to check the availability of classrooms in a school. It includes features such as booking rooms, checking room availability, and managing bookings. The program is designed to be user-friendly and efficient, making it easy for staff to find available classrooms. I got the idea for the project due to my school being affected by the COVID-19 pandemic, which led to a need for better management. The program is built using Python in IDLE and the main library used for the GUI (Graphical User interface) is named Tkinter for easy interaction. The program is specifialised for my secondary school only, and I even made enquires for it to be tested in real time by staff at the school.

The PDF on the left consists of documenting all project analysis, design, development and testing. From detecting a problem to presenting and developing a solution , then finally testing it.
The project has six different python files named RoomID, BookID, FreeRooms, StaffID, choose_own_dates and experimenting. the first 4 listed are for chandling a specific database each. When the program is first ran by running the experimenting file, 4 databases are created. These all hold all the data the system uses.
The reaons for the multiple python files was to counter the simple layout of the code in the IDLE editor, and keep the multiple functions of the program separate. The experimenting file is the main file that runs the program, and it is where the GUI is created and all the other python files are called.

At the time, I was fascinated by databases and wanted to create a program capable of managing a large volume of data effectively. However, I also wanted to work within an environment I was comfortable with, so I chose to stick with IDLE. Naturally, this required me to learn a great deal about databases and how to integrate them effectively with Python, which turned out to be a valuable learning experience — and it also led me to discover the world of SQL. Nowadays, I’m familiar with many other languages and environments that would be more suitable for a project like this, such as Java and C#. While Python was excellent for rapid prototyping and getting started quickly, its lack of static typing, performance optimization, and native GUI support made it less ideal for scaling the project further.

Looking back at this project, it's interesting to see how much I’ve improved over the years. It highlights inefficiencies, a lack of structure, and security issues that may have eluded me at the time. Additionally, I can see how much my ability to plan and design a project has developed—this was the first time I had to approach a project with extensive planning, which inevitably impacted the quality of the code and the overall outcome." However, I am still proud of the project as it was my first major program I planned and developed over a long period of time. I hope one day to come back and improve it.
